Thin Gemini adapter. **`AGENTS.md` is the canonical instruction file—read it first.**

This file contains only Gemini-specific operating notes. It must not restate or contradict `AGENTS.md`.

## Reading order

1. Read `AGENTS.md`.
2. Follow its required reading order:
   - `SECURITY.md` for authentication, authorization, tenancy, personal data, uploads, offline data, integrations, infrastructure, or deployment.
   - `GLOSSARY.md` for unfamiliar industry terms, acronyms, measurements, regulators, standards, or workflows.
   - `frontend/AGENTS.md` and the relevant local Next.js guide before changing frontend code.
   - `docs/MODULE_BACKEND_COMPLETION_CHECKLIST.md` for active module delivery status, acceptance criteria, and release gates.
   - Relevant product-specification section in `Offshora_Product_Specification_v3.md` when product behaviour is in question.
   - Feature documentation, source, migrations, and tests as the implementation truth.
3. Return here only for the Gemini-specific notes below.

## Before coding

State:

- which feature, application, or module from `docs/MODULE_BACKEND_COMPLETION_CHECKLIST.md` the task belongs to;
- whether database migrations or schema alterations are involved; and
- whether API, event, sync, or external integration contracts are affected.

## Gemini / Antigravity discipline

- Read the narrowest authoritative evidence before diagnosing a bug, designing a model, or editing an endpoint.
- Batch independent tool calls (reads, greps, commands) to minimize latency and round-trips.
- Keep business logic in backend domain services, never in views, serializers, admin classes, or React components.
- Enforce tenant isolation server-side on every query and mutation; client-supplied tenant IDs are never trusted.
- Verify migrations against fresh database instances and run focused two-tenant security test suites.
- For UI component work, strictly adhere to `.agents/skills/living-ui/SKILL.md` (check catalog, fetch & de-slop tokens, ingest into catalog).
- Name the exact verification performed and explicitly report any skipped or unverified checks.
- Do not pipe test commands through tools that mask exit codes.
- Never include AI attribution, "generated by", or `Co-Authored-By` trailers in git commits.

## Stop and ask when

- scope or expected business behaviour is materially ambiguous;
- domain rules (safety limits, approval chains, measurement formulas) require product-owner confirmation;
- a migration, policy, or contract change conflicts with established patterns;
- an operation would expose unverified external integrations as live; or
- an action would weaken any security, tenancy, or audit boundary established in `AGENTS.md` and `SECURITY.md`.
